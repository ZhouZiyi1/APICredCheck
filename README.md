# APICredCheck Artifact

This repository contains the artifact for APICredCheck, an automated framework for evaluating whether API credentials exposed from Android SDK integrations can be abused from unauthorized Android apps.

The artifact is organized into three top-level directories:

## Directory Structure

### Dataset

`Dataset/` contains the data needed for the experiments.
It includes the SDK list used in the study and is intended to include the source code and compiled APK files of the paired apps used for evaluation:

- `SDKList.csv`: the ranked SDK list used by APICredCheck.
- Legitimate app source code: apps that integrate the target SDKs with valid API credentials in the original experiments.
- Attacker app source code: paired apps that integrate the same SDKs but use invalid credentials and different Android identities.
- Compiled APK files: APKs built from the legitimate and attacker app projects.

In the real experiments, the legitimate apps contained valid API credentials requested by the authors from SDK providers.
For artifact release, these credentials are removed from the released app source code to prevent leakage of author-owned API credentials.
Specifically, credential values in legitimate app source code are replaced with all-zero placeholders, while credential values in attacker app source code are replaced with all-one placeholders.

To rerun the experiments, users must request their own valid API credentials from the corresponding SDK providers, insert them into the legitimate app projects, rebuild the APKs, and keep the attacker app credentials invalid as required by the experiment design.
Do not commit or publish real API credentials after replacing the placeholders.

See `Dataset/README.md` for the expected dataset layout and credential-placeholder policy.

### CodeAndLogs

`CodeAndLogs/` contains the APICredCheck implementation, the configuration file, and logs or intermediate outputs produced during execution.

Important files and directories include:

- `config.ini`: configuration options for SDK screening, legitimate app analysis, and runtime validation.
  The LLM API key is intentionally replaced with `sk-ant-api03-***`; users must replace it with their own valid key before running LLM-assisted steps.
- `doc_direct_analyzer.py`: performs LLM-assisted SDK screening over `SDKList.csv`.
- `apk_analyzer.py`: analyzes legitimate APKs, extracts static evidence, queries the LLM for auth points, and builds replacement profiles.
- `app_hooker.py`: performs runtime validation on attacker APKs with Frida-based instrumentation.
- `frida_server.py`: pushes and starts `frida-server` on a connected Android device.
- `*_logs/` directories: execution logs generated by different stages.
- `*_rslts/` and `*_reports/` directories: structured intermediate results and reports generated by APICredCheck.

Detailed running instructions are provided in `CodeAndLogs/README.md`.

### Results

`Results/` contains summarized experimental results.
It includes SDK screening results and the results produced by Legitimate App Analysis and Runtime Validation.

The main result files include:

- `SDKList-rslt.csv`: SDK screening results.
- `doc_direct_summary.csv` and `doc_direct_summary.xlsx`: summarized SDK screening outputs.

Additional result files generated by APK analysis and runtime validation may be copied here from `CodeAndLogs/` when preparing the final public artifact.

See `Results/README.md` for the result-file description and mapping to the APICredCheck pipeline stages.

## Security and Ethics Notes

This artifact is intended for defensive security research and reproducibility review.
The released code and dataset should not contain real API credentials owned by the authors.
Users who rerun the experiments must use their own developer accounts and credentials, follow SDK provider terms, and avoid publishing attacker apps or using third-party credentials.

The attacker apps in this artifact are designed only for controlled validation of SDK credential protection mechanisms.
They should not be uploaded to public app stores or used against real applications.
